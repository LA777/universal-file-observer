# Project Guidelines

## File Naming Constraints
- **Mandatory Prefix:** Every single markdown (`.md`) or text (`.txt`) file you suggest, draft, or create **must** begin with the `AI_` prefix.
- **Examples:** `AI_migration_plan.md`, `AI_endpoint_notes.txt`.
- **Reason:** This ensures compliance with local repository `.gitignore` rules. Never omit this prefix for text or markdown outputs.

## Project Documentation
- Internal documentation and technical specifications generated by AI are explicitly named with the `AI_` prefix to separate them from tracked source code.
- All `AI_` files live in the `_docs/` folder (gitignored). Consult them (start with `_docs/AI_CODEBASE_INDEX.md` — full back-end/front-end index) to understand active project patterns, constraints, and business logic before proposing changes.

## What This Project Is
UFO (Universal File Observer): ASP.NET Core Web API (**.NET 10**) + **Angular 22** SPA for snapshot-based file system indexing. Users create point-in-time snapshots of folders (tree + per-file SHA-256 + PC/drive/volume identity), then browse, search, label, and delete them. There is **no FileSystemWatcher and no background service** — snapshots are explicit.

## Architecture Rules (do not violate)
- **Persistence is SQLite via Dapper with raw SQL** (`Ufo.Database/SqlScripts.cs`). No EF Core, no migrations — schema is idempotent `CREATE TABLE IF NOT EXISTS` DDL executed at startup by `DapperDataContext.InitiateDatabaseAsync`.
- **IDs are Ulid everywhere**: Dapper type handlers (`SqlUlidTypeHandler`), `UlidJsonConverter` for JSON, `UlidSchemaFilter` for OpenAPI. Never introduce int/Guid keys.
- **All data is per-user**: every entity has `UserId`; every repository query must filter by it. Controllers get the user id from JWT via `[JwtClaimsRequired]` → `HttpContext.Items["UserId"]` (`HttpContextExtension.GetUserIdAsUlid`).
- Layering: `Ufo.Abstractions` (contracts) ← `Ufo.Database` (Dapper repos) ← `Ufo.Server` (controllers/services/mappers). Entities never leave the server — map to DTOs via the static mappers in `Ufo.Server/Mappers/`.
- **Version is `major.minor.patch` and written down once**: the `<Version>` element of `Ufo.Server.csproj`. The build stamps it into the assembly metadata; `ApplicationVersionService` reads it back for the startup log and `GET /api/version` (authenticated), and the Angular About tab fetches it rather than bundling it. `Ufo.Desktop.csproj` reads the same element via its `InheritApplicationVersion` target. Never add a second place that states the version. See `_docs/AI_VERSIONING.md`.
- Auth: short-lived JWT access token (HmacSha256, `ClockSkew = 0`, `JWT:TokenLifetimeMinutes`, default 30) renewed by a **rotating refresh token** in an HttpOnly/Secure/SameSite=Strict cookie scoped to `/api/auth` (`RefreshTokenCookie`). Refresh state lives in the `RefreshTokens` table as a SHA-256 hash with a sliding deadline (`JWT:RefreshTokenLifetimeDays`, 14) and an absolute cap (`JWT:RefreshTokenAbsoluteLifetimeDays`, 30); rotation is a conditional UPDATE on `RevokedAt IS NULL`, and a token replayed more than 30s after its rotation revokes every session for that user. The access token stays unrevocable by design — revoking a session ends its refresh token, not access tokens already issued — so keep its lifetime short. `UfoHost.ValidateJwtLifetimes` refuses to start on a non-positive lifetime or an absolute cap below the sliding one. Passwords hashed with BCrypt (per-password salt, no application-wide pepper). Config keys: `JWT:{Key,Issuer,Audience,TokenLifetimeMinutes,RefreshTokenLifetimeDays,RefreshTokenAbsoluteLifetimeDays}`. `JWT:Key` is a secret and is **never** committed: set it via user-secrets for development or `JWT__Key` for a deployment. `UfoHost.ValidateJwtSigningKey` refuses to start on a missing, short, placeholder, or previously-leaked key.

## Front-end Rules
- **Bootstrap path is `ufo.client/src/main.ts`** (standalone `bootstrapApplication`). `app.module.ts` / `app-routing.module.ts` are legacy leftovers and NOT active — wire routes, providers, and interceptors in `main.ts`. The active HTTP interceptor is `JwtInterceptor`, which attaches the bearer token and, on a 401, refreshes once and replays the request before giving up (the legacy `AuthInterceptor` is gone). Route access is gated on the token's `exp`, not on a stored username: `AuthGuard` for the app pages, `RootRedirectGuard` for `/`; both fall back to a refresh before sending anyone to `/login`. `AuthService.refreshSession()` must stay single-flight — concurrent rotations are indistinguishable from a stolen token and end every session.
- API calls use relative `/api/...` paths (no base URL in environments). Dev traffic goes through `src/proxy.conf.js` → `https://localhost:7150`.
- `src/environments/environment.ts` is gitignored — copy from `environment.example.ts` if missing.
- UI is Angular Material (prebuilt `deeppurple-amber` theme); global layout tweaks in `src/styles.css`.

## Common Commands
- Backend run: `dotnet run --project Ufo.Server --launch-profile https` (Swagger at `https://localhost:7150/swagger`). Requires `JWT:Key` in user-secrets — the host refuses to start without one and no key is committed.
- All backend tests: `dotnet test Ufo.sln`
- Frontend dev: `npm start` in `ufo.client/` (ng serve with SSL + proxy)
- Frontend deploy into server: `build-frontend.ps1` at repo root (builds Angular, copies `ufo.client/dist/ufo.client` → `Ufo.Server/wwwroot`; verify with `check-wwwroot.bat`)
- Production-style app URL: `https://localhost:55000` (Kestrel `App` endpoint; server opens the browser on startup)

## Known Quirks
- Server-side `SnapshotService` is a stub (`NotImplementedException`); snapshot creation logic currently lives inside `SnapshotController` (`CreateFolderTree`, `GetFolderSha256Hash`).
- `WeatherForecastController` / `ForecastComponent` are scaffold leftovers marked for removal.
- Functional tests set env `FunctionalTesting` — `Program.cs` uses `IsFunctionalTesting()` to skip DB init and browser launch; keep new startup side-effects behind that guard.
