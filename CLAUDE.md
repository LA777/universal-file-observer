# Project Guidelines

## File Naming Constraints
- **Mandatory Prefix:** Every single markdown (`.md`) or text (`.txt`) file you suggest, draft, or create **must** begin with the `AI_` prefix.
- **Examples:** `AI_migration_plan.md`, `AI_endpoint_notes.txt`.
- **Reason:** This ensures compliance with local repository `.gitignore` rules. Never omit this prefix for text or markdown outputs.

## Project Documentation
- Internal documentation and technical specifications generated by AI are explicitly named with the `AI_` prefix to separate them from tracked source code.
- All `AI_` files live in the `_docs/` folder (gitignored). Consult them (start with `_docs/AI_CODEBASE_INDEX.md` — full back-end/front-end index) to understand active project patterns, constraints, and business logic before proposing changes.

## What This Project Is
UFO (Universal File Observer): ASP.NET Core Web API (**.NET 10**) + **Angular 22** SPA for snapshot-based file system indexing. Users create point-in-time snapshots of folders (tree + per-file SHA-256 + PC/drive/volume identity), then browse, search, label, and delete them. There is **no FileSystemWatcher and no background service** — snapshots are explicit.

## Architecture Rules (do not violate)
- **Persistence is SQLite via Dapper with raw SQL** (`Ufo.Database/SqlScripts.cs`). No EF Core, no migrations — schema is idempotent `CREATE TABLE IF NOT EXISTS` DDL executed at startup by `DapperDataContext.InitiateDatabaseAsync`.
- **Changing the schema of a database that already exists**: a new *table* is just another `CREATE TABLE IF NOT EXISTS` and reaches deployed databases on the next start. A new *column* does not — `CREATE TABLE IF NOT EXISTS` is a no-op against a table that is already there, so editing the DDL alone gets you a column that only ever appears on fresh installations. Add it through `EnsureColumnAsync` in `DapperDataContext` as well (it inspects `pragma_table_info` first, because SQLite has no `ADD COLUMN IF NOT EXISTS`). Prefer a new table where the choice is open: it needs no second step.
- **IDs are Ulid everywhere**: Dapper type handlers (`SqlUlidTypeHandler`), `UlidJsonConverter` for JSON, `UlidSchemaFilter` for OpenAPI. Never introduce int/Guid keys.
- **All data is per-user**: every entity has `UserId`; every repository query must filter by it. Controllers get the user id from JWT via `[JwtClaimsRequired]` → `HttpContext.Items["UserId"]` (`HttpContextExtension.GetUserIdAsUlid`).
- Layering: `Ufo.Abstractions` (contracts) ← `Ufo.Database` (Dapper repos) ← `Ufo.Server` (controllers/services/mappers). Entities never leave the server — map to DTOs via the static mappers in `Ufo.Server/Mappers/`.
- **Version is `major.minor.patch` and written down once**: the `<Version>` element of `Ufo.Server.csproj`. The build stamps it into the assembly metadata; `ApplicationVersionService` reads it back for the startup log and `GET /api/version` (authenticated), and the Angular About tab fetches it rather than bundling it. `Ufo.Desktop.csproj` reads the same element via its `InheritApplicationVersion` target. Never add a second place that states the version. See `_docs/AI_VERSIONING.md`.
- Auth: short-lived JWT access token (HmacSha256, `ClockSkew = 0`, `JWT:TokenLifetimeMinutes`, default 30) renewed by a **rotating refresh token** in an HttpOnly/Secure/SameSite=Strict cookie scoped to `/api/auth` (`RefreshTokenCookie`). Refresh state lives in the `RefreshTokens` table as a SHA-256 hash with a sliding deadline (`JWT:RefreshTokenLifetimeDays`, 14) and an absolute cap (`JWT:RefreshTokenAbsoluteLifetimeDays`, 30); rotation is a conditional UPDATE on `RevokedAt IS NULL`, and a token replayed more than 30s after its rotation revokes every session for that user. The access token stays unrevocable by design — revoking a session ends its refresh token, not access tokens already issued — so keep its lifetime short. `UfoHost.ValidateJwtLifetimes` refuses to start on a non-positive lifetime or an absolute cap below the sliding one. Passwords hashed with BCrypt (per-password salt, no application-wide pepper). Config keys: `JWT:{Key,Issuer,Audience,TokenLifetimeMinutes,RefreshTokenLifetimeDays,RefreshTokenAbsoluteLifetimeDays}`. `JWT:Key` is a secret and is **never** committed: set it via user-secrets for development or `JWT__Key` for a deployment. `UfoHost.ValidateJwtSigningKey` refuses to start on a missing, short, placeholder, or previously-leaked key.

## File-system Writes (`FileSystemController`)
`POST /api/filesystem/{create,rename,copy,move,delete}` change the disk. Two checks stand between a request and a write, and they are not interchangeable:
- **`IPathGuard` decides which folders may be touched.** It resolves symlinks at *every* path component, so what comes back is the real path — which also means a destructive operation aimed at a link would hit its target. Rename, move and delete refuse a symlink for that reason; copy follows one, which is harmless.
- **`IFileNameValidator` decides what a name may be**, and rejecting path separators is the whole of what keeps a name a name. Every write joins a caller-supplied name to a guard-approved folder, so a separator getting through is a write outside that folder.
- An **allowed root is not writable as an object**: it resolves *inside* the allow-list because it is the allow-list, so the guard says yes while renaming or moving it writes to its parent. `IsProtectedRoot` is the check; rename, move and delete all use it.
- **Batch operations answer `200` with per-entry failures.** Nineteen files copied and one locked is not a failed request. Only a malformed request is a 4xx. A collision comes back flagged `IsConflict` so the caller can ask the user rather than overwriting on its own.
- Never delete a destination before writing its replacement unless the *kind* changes (file over folder or the reverse) — a failure in between leaves the user with neither.

## Per-user UI State (shortcuts, folder tabs)
Two features store what the user has arranged. Both learned the same lessons the hard way:
- **Store only what differs from the build's default.** `UserKeyBindings` has a row only for a rebound action; resetting is the *absence* of a row. That way re-keying a default in a later release reaches everyone who never had an opinion. An empty value is still a real preference ("no key at all") and is not the same as no row.
- **Never let a client's picture of the other rows drive a write.** `FolderTabs` writes one row per call (`POST /api/foldertabs/{lock,unlock}`), never a wholesale replace: a replace makes the client authoritative about tabs it may have failed to load, and a client that loaded none would delete them all. Where a whole-table save is genuinely required — the shortcuts page, because "no chord does two jobs" spans rows and a *swap* must be expressible — validate against the table the save will **produce**, not the rows the request happens to name.
- **Re-check stored paths on read as well as write.** The allow-list is configuration and can be tightened between sessions; a folder tab locked while the server was unrestricted must not restore a path it may no longer open.

## Front-end Rules
- **Bootstrap path is `ufo.client/src/main.ts`** (standalone `bootstrapApplication`). `app.module.ts` / `app-routing.module.ts` are legacy leftovers and NOT active — wire routes, providers, and interceptors in `main.ts`. The active HTTP interceptor is `JwtInterceptor`, which attaches the bearer token and, on a 401, refreshes once and replays the request before giving up (the legacy `AuthInterceptor` is gone). Route access is gated on the token's `exp`, not on a stored username: `AuthGuard` for the app pages, `RootRedirectGuard` for `/`; both fall back to a refresh before sending anyone to `/login`. `AuthService.refreshSession()` must stay single-flight — concurrent rotations are indistinguishable from a stolen token and end every session.
- API calls use relative `/api/...` paths (no base URL in environments). Dev traffic goes through `src/proxy.conf.js` → `https://localhost:7150`.
- `src/environments/environment.ts` is gitignored — copy from `environment.example.ts` if missing.
- UI is Angular Material (prebuilt `deeppurple-amber` theme); global layout tweaks in `src/styles.css`.
- The Files tab is two `FilePanelComponent` panes. Each owns its **folder tabs** and each tab its own history, so Back never crosses between tabs. Copy and Move target *the other pane's* folder — `FilesComponent` feeds each panel the opposite path.
- **Keyboard shortcuts are data, not key names in code.** `KeyBindingsService.actionFor(event)` answers what a keypress means; the panes only decide whether that action can run now. The catalogue (ids, labels, defaults) lives on the server in `KeyBindingActions` — the client holds ids alone, so adding an action is a server change plus the code that performs it.
- `shared/key-chord.ts` is the single spelling of a chord (`Ctrl+Alt+Shift+Key`), used by both the capture box and the panes. If those two ever disagree, a shortcut records perfectly and then never fires.

## Common Commands
- Backend run: `dotnet run --project Ufo.Server --launch-profile https` (Swagger at `https://localhost:7150/swagger`). Requires `JWT:Key` in user-secrets — the host refuses to start without one and no key is committed.
- All backend tests: `dotnet test Ufo.sln`
- Frontend dev: `npm start` in `ufo.client/` (ng serve with SSL + proxy)
- Frontend deploy into server: `build-frontend.ps1` at repo root (builds Angular, copies `ufo.client/dist/ufo.client` → `Ufo.Server/wwwroot`; verify with `check-wwwroot.bat`)
- Production-style app URL: `https://localhost:55000` (Kestrel `App` endpoint; server opens the browser on startup)
- Container: `docker compose build && docker compose up -d` (HTTPS on 8443, self-signed on first run). The image builds the Angular app itself, so no `build-frontend` step is needed first. `UFO_JWT_KEY` must be set in `.env`.
- **The container mounts two roots**: `/library` read-only — the tree to index, where the write endpoints are refused by the file system rather than by UFO — and `/workspace` read-write, which is what the file operations are for. Both are in `Ufo__AllowedRoots`. A `/workspace` bound to a host path must be writable by the image's `$APP_UID` (1654); the default named volume avoids that because Docker seeds it from the image directory, which is why `/workspace` is created in the Dockerfile rather than left to Docker.

## Known Quirks
- Server-side `SnapshotService` is a stub (`NotImplementedException`). Snapshot tree-walking, hashing and folder-hash composition live in `Ufo.Server/Services/FolderTreeBuilder.cs` (`BuildAsync`, `GetFolderSha256Hash`), which `SnapshotController` injects as `IFolderTreeBuilder` — not in the controller itself.
- **`FileExtension` is stored *with* its leading dot** (`.txt`), because that is what `FileInfo.Extension` gives and it is written verbatim by both the snapshot walk and the browse endpoint. Reassemble a file name as `Name + FileExtension` — never `Name + "." + FileExtension`, which produced `notes..txt` in every folder hash until it was fixed. An extensionless file stores `""`, so the concatenation is total and needs no special case.
- The `Name`/`FileExtension` split is mildly lossy: `Path.GetExtension("notes.")` is `""`, so a Linux file named `notes.` is indexed as `notes`.
- `WeatherForecastController` / `ForecastComponent` are scaffold leftovers marked for removal.
- Functional tests set env `FunctionalTesting` — `Program.cs` uses `IsFunctionalTesting()` to skip DB init and browser launch; keep new startup side-effects behind that guard.
